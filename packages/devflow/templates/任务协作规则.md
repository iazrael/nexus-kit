# 任务协作规则

> 基准：nexus-devflow task 使用诊断 / 2026-10-15

本规则是宿主可拷贝的起点。宿主填写自己的开发、验证和审批规则，并在 nexus.config.json.task.rules 登记规则文件。目标、范围、输入指纹、白名单和复跑命令只写在任务文件，模型与时间预算使用任务配置及宿主默认值，不在提示词另存一份。

执行者读取任务与公共规则，通过派发提示词中的 task start 入口建立或恢复指定工作树。执行者核对分支和输入副本，建树后只改白名单，不改主仓或其他树，不自行领取其他任务，不自动合入、推送、发布或回收。工作树和只读副本是协作约束，不是系统沙箱。

执行者分阶段提交，并在同一任务记录命令、结果、失败、检查点与下一步。首轮预算只是检查进度的节点；卡住或缺少原料时保留失败证据并标受阻，不擅自扩范围、换方法定义或重建会话。中断后使用原树和原会话接续。单条长命令建议控制在约 20 分钟内，按可恢复阶段拆分并留下检查点；这个时长是操作建议，不是执行器接口保证，任务预算不能延长执行器自身等待上限。并发执行器共享账号额度，429 可能让多个在跑任务一起失败；恢复前先确认额度和原会话。

执行者只标待验收或受阻。协调者独立复跑、核对输入和输出指纹、安排独立代码审查；产品行为改变时还安排独立产品评审。审查材料绑定被验证提交，代码或材料变化后重验。待验收任务有缺陷时，协调者先用 task rework --message-file 登记 defects、reproduce、criteria，再显式 resume；交付和基准都无需调整时继续验证与验收。通过只表示已登记的验证和审查范围，不证明未验证范围。

验证命令使用工具预建的新空输出目录，不限定父目录，拒绝复用非空旧结果，不覆盖原始证据。外部命令使用 argv，不拼 shell。外部输入在边界校验，密钥只经环境变量传入，不能进入任务、配置、提示词或日志。错误与跳过的步骤明确报告。

定义变更先走宿主审批，在原任务树提交后重新确认。原始运行、验证和审查材料由协调者归档，树回收前核对归档完整性。旧快照由对应工具版本读取，不改版本号绕过兼容检查。任务通过后的集成与发布仍遵守宿主工程规则。已派发起点不改写历史；固定起点脱离主仓时，待验收任务先正式登记基准改写的返工原因，再在原树核对、变基或重放交付，重新确认基准并交付、验证和审查。add/add 冲突逐文件核对，不统一取某一边。集成前检查主仓 status 和执行窗口内的新增提交；主仓干净也可能已有越权内容进入提交。

报告遵守宿主文档规范。正文只写当前事实，判断注明具体对象与证据；帮助输出只证明命令名称，启发式只作初筛，不能写成完整行为验证。可再生成的条数、行数、覆盖率指向检查命令，不写死在正文；配置字段和函数细节以源码为准，不另抄一份。
