# 任务协作规则

> 基准：nexus-devflow task 执行者规则 / 2026-11-01

执行者必读，只有这一页。任务卡里的目标、设计和验收清单是全部要求；宿主拷贝后在 nexus.config.json 的 task.rules 登记，宿主的领域须知由任务卡按小节引用。输入指纹、空输出目录、工作树干净和交付状态由工具检查，这里不重复。

## 怎么做

1. 读任务卡，运行派发提示里的 `task start`。派发表示任务卡列出的范围已批准，范围内直接做。返工时照任务卡最新一条返工要求逐项改。
2. 按设计实现，分阶段提交。实测和设计冲突时停下，留证据后用 `task block` 登记受阻，不自己改方案。
3. 按验收清单逐条自验，负例也要跑，记录实际证据并提交，再运行 `task deliver`。deliver 复跑验证命令、追加交付摘要、标待验收。做不到就用 `task block` 写明缺口和恢复入口。最终回复给交付 SHA 并复述交付摘要。

交付摘要文件放在工作树外，格式自由。建议说明结果、验证和遗留问题，例如：

```
改了什么：结果、关键变化、产物路径
验证如何：可直接复制执行的命令和关键输出
还有什么：未验证范围、跳过的检查、遗留风险；没有写「无」
```

## 注意

1. 每句「已实现、已实测、已排除」都要指向本轮产物；没做就写没做。否定结论要附排除实验。
2. 按任务目标和范围修改需要的文件，无需预先登记路径。扩范围、改验收目标或新增未授权动作，先交回协调者。
3. 同一方法失败三次就停，留下现场和恢复命令。密钥只走环境变量，错误不吞。
