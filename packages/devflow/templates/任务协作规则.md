# 任务协作规则

> 基准：nexus-devflow task 执行者规则 / 2026-10-24

本文件是执行者必读的规则，宿主拷贝后改成自己的版本，在 nexus.config.json 的 task.rules 登记。目标、范围、输入、白名单和复跑命令只写在任务文件；协调者怎样写任务、复跑和验收写在宿主自己的任务文档，不放进本文件。

## 开工

- 用派发提示词里的 task start 命令建立或恢复工作树，核对分支和输入副本。
- 只在自己的任务树里改白名单内的文件，不改主仓、其他树和输入副本。删除基准里已有的文件，要先在任务配置 deletable 里登记。
- 派发表示已批准任务文件列出的范围，范围内直接做。扩范围、改验收目标或新增未授权动作时，保存证据交回协调者。
- 返工时以任务文件里最新一条返工要求为准，逐项对照缺陷、复现命令和通过标准。

## 过程

- 分阶段提交。执行记录每阶段只写结论、检查点和下一步；探索细节写进宿主指定的笔记文件。
- 卡住或缺原料时保留失败证据并标受阻，不擅自扩范围或换方法。同一方法失败三次就停。
- 预算是进度检查节点，不是硬期限。单条长命令控制在约 20 分钟内，拆成可恢复的阶段。
- 中断后用原树和原会话接续。
- 验证命令接受工具预建的空输出目录，拒绝非空旧目录，不覆盖原始证据。
- 外部命令用 argv，不拼 shell。密钥只经环境变量传入，不写进任务、提示词或日志。错误和跳过的步骤如实写出。

## 交付

- 只标待验收或受阻。通过、合入、推送和发布由协调者做。
- 每轮标待验收前，在任务文件「交付与验收记录」末尾追加交付摘要，随交付一起提交；返工时追加新的，不覆盖旧的：

  ```
  - <时间> 交付摘要
    1. 改了什么：结果、关键变化、产物路径与指纹
    2. 验证如何：可直接复制执行的命令和关键输出
    3. 还有什么：未验证范围、跳过的检查、遗留风险；没有写「无」
  ```

- 最终回复给交付 SHA，并复述同一份交付摘要。
- 报告只写当前事实。可再生成的条数、行数、覆盖率指向检查命令，不写死。
