# Web 运行时开发规范

> 基准： 0.7.0 / 2026-10-15

本篇规定影响用户状态、交互手感和长会话稳定性的跨模块合同。违反任何一条即返工。

## 1. 刷新与升级

1. **任何路径不得在用户未点击时刷新页面**。刷新只发生在升级弹窗「确定」、「强制更新」，
   或白屏兜底页「重新加载」之后（后者会先激活已下载好的新版本，是不经升级弹窗确认的唯一例外）。
2. 升级、退出、返回首页这类主动离场流程固定为：收集当前数据 → 等待持久化完成 → 再跳转或刷新。写入失败
   留在当前页面并给出可见提示；等待必须有上限，超时按失败处理，不得让用户卡在既不离场也无提示的状态。
3. 需要专注的流程中暂缓升级弹窗（`setPromptBlocked`），流程结束解除。
4. `pagehide`/`beforeunload` 只作无法控制的关页兜底，不构成可靠保存承诺。

## 2. 持久化

5. 写入按快照产生顺序串行执行，旧快照不得晚到覆盖新快照。
6. 每个持久字段同步维护收集、schema、恢复、迁移与 round-trip 测试；关键字段的派生值要有绝对值断言，
   只断言「恢复 = 存档时」挡不住两边同错。
7. 改结构直接升 schema 版本并写迁移；坏记录与未知版本不得删除，用户应能识别并导出原始记录。
8. 导入文件先限制体积和结构复杂度，再按 schema 校验和迁移。
9. 用户产生值得保存的数据后申请持久化存储（`requestPersistentStorage`），被拒不阻塞。

## 3. 页面生命周期

10. 页面隐藏时清除持续态输入（长按、拖动、按键态）、暂停音频与动画、请求保存；恢复时先重置时间基线，
    再恢复音频与渲染，不得补跑后台期间的逻辑。
11. 全局监听必须有明确 owner 和释放路径；窗口失焦、页面隐藏、指针取消、触控中断时持续态必须清除。

## 4. 输入

12. 文本输入、可编辑区域和输入法组字期间，快捷键与调试热键必须全部让路。
13. 模态窗口、普通窗口与页面动作按从专用到普通的顺序仲裁，一个按键不得穿透到多个职责。

## 5. 异步资源与所有权

14. timer、RAF、DOM listener、Observer、AudioBuffer、object URL、fetch 都必须有唯一 owner，并提供对称的
    清理（clear/remove/disconnect/revoke/abort）。
15. 页面/场景切换的异步任务必须用 AbortSignal 或代际令牌；旧页面迟到的结果不得写入新页面状态。
16. 资源加载失败必须进入结构化日志，并选择明确结果：阻断、用户可见重试、或登记过的占位降级；禁止静默
    留下半加载状态。

## 6. 运行时数据边界

17. 网络 JSON 先检查 HTTP 状态，再以 `unknown` 读取并经解析器校验。
18. 解析器负责必要字段、版本、数值域与集合结构：关键数据非法时 fail-fast，只有可选表现数据才允许带日志降级。
19. 同一种格式只保留一个解析入口。

## 7. 首屏与加载

20. 首屏关键路径只放首屏第一眼要用的东西；SW 注册推到空闲期（`startWhenIdle`），其余预取排在首屏之后。
21. 批量下载限并发并行，禁止 `for (…) await load(…)` 串行——高延迟链路上等于「请求数 × 单次延迟」。用
    `@nexus-kit/runtime/assets` 的 `mapLimit` 或加载调度器；首屏要先出来的资源挂关键闸门（`loader.hold`），不急的排低档位。
22. 同一份资源禁止下载两次：图片经 `createImageCache`，其他资源经加载调度器按 URL 去重。每次成功的 `acquire` 都要有
    对应的 `release`，否则这张图永远不会被淘汰。
23. 任何等待（资源、网络、保存）都必须有超时放行，绝不能把用户关在门外。
24. 首屏与预缓存预算以 `scripts/verify-build.ts` 为唯一真相，超限先解释再调数。

## 8. 音频

25. 声音一律经 `@nexus-kit/runtime/audio`：全应用一个引擎宿主（`createAudioHost`），不另建 AudioContext；`unlock()` 在
    用户手势的回调里同步调用。解锁前的播放请求按类处理：背景音乐记下意图、解锁后补播，音效直接丢弃（样本播放器已实现）。
26. 后台挂起音频：引擎宿主开 `suspendWhenHidden`。回前台恢复（含 iOS 的 interrupted 与 statechange 兜底）、恢复无效时重建
    AudioContext（有上限、进诊断日志）由引擎宿主负责；自己接振荡器的模块订阅 `onRebuild`，在新 context 上重建节点。
27. 场景切换以最后一次背景音乐意图为准（`playMusic` 已实现：晚到的解码作废，回前台按意图校对）。开过麦克风的，停止采集后
    调 `host.resetSession()`。

## 9. 全屏与安全区

28. 可交互 UI 放进安全区容器统一吸收 `env(safe-area-inset-*)`，子元素不得各自叠加。
29. 根高度用 standalone 限定的 `100lvh` + 文档流铺满；不用 fixed 撑高、不用 JS 量屏高。
30. 关掉移动浏览器点按高亮与过度滚动回弹（模板 index.css 已配），新增全屏层沿用同一套。

## 10. 日志与诊断

31. 日志只经 `src/observe.ts` 的 `logs.log("模块名")` 记录（未捕获异常已由 `captureGlobalErrors` 自动记录），不另起日志、不散写 console；会按帧或按次刷出多条的
    事件记 debug 或单独分区，不得挤掉启动、存档、升级这类低频事件。
32. 日志里不得写密钥、令牌、完整 URL 查询串与用户隐私原文；记 URL 先过 `scrubUrl`。
32a. 自己的性能指标经 `src/observe.ts` 的 `perf.registerGauge` 登记，不另起定时器采样；读不到返回 null，不得返回 0
    （0 会被当成真实读数画进走势）。阶段耗时用 `perf.span` / `spanAsync`，有渲染循环的每帧调 `perf.frameStart` / `frameEnd`。
33. 诊断导出入口（版本号连点 5 次打开诊断面板）可以挪位置，不得删除；根组件外的错误边界与白屏兜底不得拆掉——
    「一打开就白屏」时它是唯一能导出诊断的地方。
34. 诊断文件里的「疑似异常退出」只说明上一局没有正常告别，不能据此断定崩溃或被系统杀掉。
