# 工程质量与交付规范（kit 自身）

> 基准： 0.4.0 / 2026-10-14

本篇约束 nexus-kit 仓库自身的开发与发布。宿主应用的规范在模板 `templates/webapp/docs/规范/`。

## 1. 完成标准

1. 改动以 `pnpm check` 全绿为完成标准：文档审计、lint、格式、类型、单测、包构建、dist 新鲜度、主包加载失败兜底脚本的 ES5 门禁、模板
   单测与模板构建（含 verify-build）。任何一步失败都算未完成。
2. 动了 pwa / pwa-react / vite 的升级链相关代码，加跑 `pnpm e2e`（真浏览器升级链）。
3. 产品源码覆盖率四项 ≥80%（`pnpm test:coverage`）；降阈值、写只为做绿的测试属造假。

## 2. 代码边界

4. pwa 不依赖任何框架，DOM/SW 访问只在函数体内（Node 里 import 不得报错）。
5. pwa-react 只出 hook，不写样式、不带文案。
6. 包之间只用 peerDependencies 互引，kit 内开发用 devDependencies 的 `workspace:*`。
7. 外部输入（version.json、nexus.config.json、URL 参数、浏览器 API 返回值）在边界作 unknown 校验。
8. 副作用（命令执行、网络、存储、时钟）经依赖注入，决策逻辑必须可单测。
9. 有明确输入输出的逻辑先写测试；bug 修复先用失败测试钉住，并在[平台坑账](../架构算法/平台坑账.md)登记。

## 3. 构建产物与分发

10. `packages/*/dist` 入库，和源码同提交：流程是「改源码 → `pnpm build` → `git add` → `pnpm check` → 提交」，
    `pnpm check` 构建后断言 dist 没有未暂存的变化。
11. 消费方经 git 子目录依赖钉 tag 安装；tag 为 `v<版本>`，`packages/` 下全部包同版本号同 tag。

## 4. 版本与发布

12. 版本按语义化：只加能力 → 次位；修复 → 末位；**破坏接入方**（改函数签名、改配置字段、改默认行为、
    提高 peer 版本下限）→ 0.x 阶段进次位并在 CHANGELOG 写「破坏性：」条目与迁移方法。
13. 发布链：整合 CHANGELOG 落款 → `packages/` 下全部包的 package.json 同步改版本 → `pnpm check` + `pnpm e2e` 全绿 →
    提交 → `git tag v<版本>` → 推送分支与 tag。
14. CHANGELOG 是 kit 变更的唯一台账，源码改动必须附条目（precommit 门禁）。

## 5. 并行开发

15. kit 遵守自己交给宿主的工作树纪律：改动一律在工作树里做，`pnpm worktree:new <分支名>` 建树（Claude 的
    `--worktree` 与子 Agent 隔离经 `.claude/settings.json` 钩子走同一入口），不得手工 `git worktree add`，不用
    `git stash`。机制见[并行开发与发版](../架构算法/并行开发与发版.md)。
16. 合入前在工作树 `pnpm check` 全绿、独立评审过，`git rebase main` 后在变基后的代码上重新验证（变基带进了别人新加的依赖、锁文件变了的话，先 `pnpm install`）；合入只走
    `pnpm worktree:merge <分支名>` 单独执行，脚本只快进、合入后在主仓库先按锁文件装依赖再跑 `pnpm check`，失败即继续修。确认合入成功
    后 `pnpm worktree:rm <名称>` 回收。
17. 发版（§4）在主仓库 main 上做，不在工作树里打 tag。

## 6. 文档

18. 文档按需求 / 架构算法 / 规范 / 设计 / 存档分层，写法同模板《文档写法规范》；每篇活文档头部有基准行，
    登记在 CLAUDE.md 索引，`pnpm docs:check` 拦截。
19. 改机制的同一提交更新对应架构文档；改接入方必须遵守的规则同提交更新《接入规范》。
