# 接入规范

> 基准：0.8.0 / 2026-10-19

宿主应用接入 nexus-kit 必须遵守的规则。违反任何一条即返工。机制见
[离线与升级](../架构算法/离线与升级.md)、[部署与回滚](../架构算法/部署与回滚.md)、
[并行开发与发版](../架构算法/并行开发与发版.md)、[日志与诊断](../架构算法/日志与诊断.md)。

## 1. 起步

1. 新项目一律 `pnpm init-app <目录>` 从模板生成，不手抄模板文件。
2. kit 依赖钉 tag，升级 kit = 改 tag 后跑 `pnpm check` 与真机升级走查；**不得**指向分支或 commit。
3. 老项目接入时，先删掉被 kit 取代的本地实现，再接 kit——两份实现并存等于没收敛。

## 2. PWA 红线

4. SW 注册只经 `createPwaController`，全应用一个实例；**不得**再用 vite-plugin-pwa 的自动注入或
   自己调 `navigator.serviceWorker.register`。
5. **任何路径不得在用户未点击时刷新页面**。刷新只发生在升级弹窗「确定」、「强制更新」，或白屏兜底页「重新加载」
   按钮之后；兜底页的重新加载会先激活已下载好的新版本，是不经升级弹窗确认的唯一例外（需求裁决）。
6. 升级前有未保存数据的应用，必须把保存接进 `confirm(beforeUpgrade)`；保存失败返回 false，用户留在
   弹窗上重试。保存有超时（默认 5 秒），保存钩子不得依赖用户再操作。强制更新的保存钩子失败只记日志、照常更新。
6a. 「强制更新」入口由项目自行挂载（设置页、调试面板、错误页等），调 `usePwaUpdate().forceUpgrade`；模板不内置。
    注意升级弹窗由用户手上的旧版本渲染，入口要在第一个上线版本里就挂好，后续版本补不救已装的旧版。
7. 需要专注、不能被打断的流程（答题、对局、输入）用 `setPromptBlocked(true)` 暂缓弹窗，流程结束解除。
8. PWA 配置只写在 `pwa.config.ts`，vite.config 与 verify-build 都从它取；**不得**在两处各写一份。
9. 按需资源（文件名不带哈希）必须落进声明的运行时分区；新增按需资源目录时同步改分区声明，构建会
   按 public 实测对账。
10. 宿主代码必须引用 `__APP_NOTES_DIGEST__`（模板的 `build-info.ts` 已接好），否则构建门禁失败——
    同版本重发的判定依赖它。
11. `pnpm build` 必须是 `vite build && node scripts/verify-build.ts`；预算超限先解释原因再调数，调数和
    交付说明一起走。

## 3. 版本与 CHANGELOG

12. 产品版本只在 package.json 人工维护，纯 `X.Y.Z`；构建号由计数器自动递增，**不得**手改或入 git。
13. 源码改动必须附 CHANGELOG 条目（precommit 门禁）；用户无感的记「内部：」，未开放功能记「WIP：」。
    发版时整合 Unreleased、落款 `## [版本] - 日期`，落款条目整段进升级弹窗，写大白话。

## 4. 全屏与安全区

14. 保留模板 index.html 的 viewport-fit=cover 与 apple meta；改 apple meta 后要删主屏图标重装才生效，
    重装会清掉站点数据——有本地数据的应用先提供导出。
15. 可交互 UI 放进 `.safe-area` 容器，子元素**不得**各自再叠加 `env(safe-area-inset-*)`。
15a. iOS 上 Safari 与主屏应用存储隔离：有本地数据的应用必须提供导出/导入，安装引导放在首次使用早期并写明
    记录不会带过去。
16. 根高度沿用模板的 `100lvh`（standalone 限定）+ absolute 铺满方案，**不得**改用 JS 量屏高。

## 5. 部署

17. 部署只走 `pnpm run deploy`（`nexus-devflow deploy`；**不能**写 `pnpm deploy`，会被 pnpm 内置命令遮蔽），只在主仓、发布分支、工作树干净、刚构建完时执行。
18. 服务器 nginx 以 kit 样板为起点；更新链关键文件的缓存头属于门禁，改动必须线上验证。
19. 实机验收 URL 一律带 `?nosw=1`；裸 URL 看到旧页面先怀疑 SW 壳，再怀疑代码。

## 6. 并行开发与发版

20. clone 后与每次升级 kit 后执行一次 `pnpm hooks`（`nexus-devflow install-hooks`）：它把 `core.hooksPath` 指到
    `.githooks`，并写入 CHANGELOG 门禁与发版锁钩子（已存在的同名钩子不覆盖）。`.githooks/` **必须**入库：
    `core.hooksPath` 是相对路径，git 在每个工作树里按该树的根目录找钩子，不入库的工作树里没有任何钩子。
    宿主自己改过 `.githooks/reference-transaction` 的，要把 kit 样板的发版锁判断并进去，否则发版锁不生效。
20a. 存量项目的 worktree、task、release、install-hooks 直接调用 PATH 上的 `nexus-devflow`，跟随 kit 主干；
    模板生成的项目在 devDependency 里钉 tag，`pnpm` 脚本优先用 `node_modules/.bin` 里钉住的版本。前提是
    PATH 上有 `nexus-devflow`：没有、换了机器或软链悬空时，在 kit 主仓库或任一工作树执行 `pnpm install-cli`。
    它把 `~/.local/bin/nexus-devflow`（`--bin-dir` 可改）软链到 kit 主仓库的 `packages/devflow/dist/cli.js`，
    目录不在 PATH 里或被同名命令遮住时打印处理办法并以非零退出。
21. 工作树只经 `nexus-devflow worktree` 建、合、收；保留模板 `.claude/settings.json` 的 WorktreeCreate /
    WorktreeRemove 钩子，**不得**手工 `git worktree add/remove`。
22. `worktree.share` 只能列不入 git 的路径；新增了要在工作树间共享的不入 git 资源（大素材目录、本地计数器），
    同步登记进 `share`，并让 `.gitignore` 用不带尾斜杠的规则忽略它（带尾斜杠的规则不匹配软链）。工作树里会
    生成、回收时可以直接删的产物目录登记进 `worktree.disposable`，否则回收会拦下它们。共享项里只读的大目录
    （档案、原料）**不得**列进 `worktree.isolatable`；缺省时全部共享项都可隔离，有这类目录的宿主必须显式登记
    `isolatable`，只列可再生的产物目录。列进 `isolatable` 的目录里不要放软链，否则复制隔离会被拒绝，只能 `--empty`。
23. 发版只走 `nexus-devflow release`；`release.steps` 必须包含完成标准、构建与部署三步，**不得**删掉验证步骤
    求快。

## 7. 日志与诊断

24. 全应用一个日志 store（模板 `src/observe.ts`），在渲染之前初始化，`startForensics` 与
    `captureGlobalErrors` 紧随其后——取证要赶在任何可能崩溃的代码之前写下本局，异常捕获要赶在第一个异常之前挂上。各模块经 `logs.log("模块名")` 记日志，**不得**另起一套日志或
    直接散写 console。pwa 控制器的 `logger` 传 `logs.log("pwa")`。
25. 会按帧或按次刷出多条的高频事件记 debug，或在 `createLogStore` 的 `domains` 里单独分区，**不得**让它们
    和低频的启动、存档、升级事件挤同一个区。
26. 日志里**不得**写密钥、令牌、完整 URL 查询串（相对路径的也算）与用户隐私原文；需要记 URL 时先过
    `scrubUrl`。导出时只兜底处理 `http(s)://` 开头的 URL。
26b. `main.tsx`（入口）第一行导入 `observe.ts`，并在根组件外包错误边界：渲染崩溃交给 `crashFallback.report`、
    挂载成功调 `onAppMounted`（模板 `observe.ts`：撤下白屏兜底、记「mounted」时间点、采一次启动画像），并给 `installCrashFallback` 传 `isBlank`（页面有没有内容）。少了这两样，
    挂载前的一个无关报错就可能在 1.5 秒后把应用整页盖住。`isBlank` 的两条义务：启动要等待（读存档、拉配置）的
    宿主，挂载前先往 `#root` 画一个加载态，否则等待期间一个无关报错会让兜底页闪现、直到挂载成功才撤下；在
    `index.html` 的 `#root` 里放了静态启动画面的宿主，要改写 `isBlank`（例如判断应用自己的根元素在不在），否则
    启动画面让 `#root` 永远「有内容」，真正启动失败时兜底不会出现、用户卡在启动画面上。
26c. 保留 `vite.config.ts` 里注入主包加载失败兜底的插件（`bootGuardScript`），以及 `observe.ts` 第一句的
    `markBooted()`——少了 `markBooted`，内联兜底会在 15 秒后盖住正常运行的应用；少了注入，主包没加载上时用户只看到
    一片白。开了 CSP 的部署要给这段内联脚本与其内联样式放行（hash 或 nonce）。
26a. 读上次退出判词用 `forensics.verdict`（随时取最新）或 `await forensics.settled`；**不得**在启动时解构出一份快照——
    Web Locks 查询落定前的初值可能还会变。
26d. 性能采集与日志同处初始化（模板 `observe.ts` 的 `createPerf` + `start()`），全应用只建一个。宿主自己的指标经
    `perf.registerGauge` 登记、阶段耗时经 `perf.span` / `spanAsync` 记，**不得**另起定时器采样或另存水位。读数函数
    读不到时返回 null，**不得**返回 0——0 会被当成真实读数画进走势；指标名不得用内置指标名与 `t`、`kind`、`session`。自己有渲染循环的宿主每帧调
    `perf.frameStart()` / `perf.frameEnd()`。用 WebGL 的宿主可装 `installGlCounter` 并把计数登记成指标。
27. 保留诊断导出入口（模板是版本号连点 5 次打开诊断面板）与白屏兜底。改界面时可以挪位置，不得删掉——用户反馈问题时这是唯一的
    现场来源。
28. 「疑似异常退出」只说明缺少正常关闭的凭证，排查时**不得**当成崩溃或被系统杀掉的结论。

## 8. 图像资源

28a. 宿主自己下载、解码的图一律经 `/assets`：全应用一个 `createLoader`、一个 `createImageCache`，创建时传 `perf`，
    位图字节进水位长线。**不得**另起一条不受调度器约束的批量下载——它会绕过并发上限和关键闸门，在慢网上把首屏挤到后面。
28b. 每次成功的 `acquire` 都要有对应的 `release`（离开页面、组件卸载时）；acquire 失败或被取消的不 release。
    不再需要的排队请求用 AbortSignal 取消。漏 release 的图永远不进 LRU，表现为 `assets.bitmapMB` 一路涨不回落。
28c. 把位图交给渲染库上传成纹理的宿主，在 `onEvict` 里销毁对应纹理：位图已经关闭，留着纹理就是一份没人管的显存。

## 9. 音频

28d. 宿主的声音一律经 `/audio`：全应用一个 `createAudioHost`。合成类宿主自己接振荡器，用 `host.context` 与总线，
    发声前过 `host.whenRunning`；用音频文件的宿主再建一个 `createSamplePlayer`，传 `loader` 与 `perf`。**不得**另建
    AudioContext——回前台恢复、假死重建、下潜都只对引擎宿主管着的那一个生效。
28e. `host.unlock()` 必须在用户手势的回调里同步调用（点击、触摸）。挂一个常驻的 `pointerdown` 兜底调用也可以，unlock 幂等。
28f. 订阅 `onRebuild` 的合成类宿主，在回调里丢掉旧 context 上建的节点和按旧时钟记的账，在新 context 上重建。
28g. 开过麦克风（`getUserMedia`）的宿主，停止采集后调 `host.resetSession()`：iOS 停麦后会把输出压到极轻，状态却还是 running。

## 10. 回流

29. 在宿主里踩到属于 kit 能力范围的新坑：回 kit 登记[平台坑账](../架构算法/平台坑账.md)、补失败测试、
    修复、发版，宿主升级 tag——**不得**只在宿主里打补丁。

## 11. 任务协作

30. 使用 task 的宿主必须在 `nexus.config.json` 登记任务目录、被 Git 忽略的控制目录、公共规则、执行器与
    时间预算；明确配置启动命令、模型、权限参数及需要剔除的环境变量。配置以包内 `task.config.example.json`
    为起点，机制见[任务协作](../架构算法/任务协作.md)。外部命令用 argv 数组，密钥只经环境变量传入，
    **不得**写入配置、任务文件、提示词或日志。
31. 任务树使用独立的 `task.worktreeDir` 与显式登记的 `task.postCreate`，**不得**接入可写共享项。
    宿主派发预检登记在 `task.preflight`。未提交的输入路径必须被 Git 忽略；输入使用校验后的只读副本，
    **不得**读取正在修改的兄弟任务代替已验收前置。依赖前置代码的任务，必须等前置合入主仓后再派发。
32. 任务必须先提交再派发，写清目标、范围、输入指纹、可写白名单与验证命令；删除已有文件须逐路径登记
    `deletable`，重命名也要授权删除旧路径。配置的 goal 只写一句话，里程碑和禁止事项放正文；背景区分
    已证事实与待证猜测，**不得**预设研究结论。
33. 验收清单每项必须写操作、预期结果、证据、负例和同机制兄弟场景，末列「自验结果」由执行者填写，
    **不得**只写“测试通过”。执行者用 `task deliver` 交付、用 `task block` 登记受阻。任务文件的交付与
    验收记录保持在最后一节，供工具追加记录。
34. `task.rules` 只登记执行者规则，协调者的任务编写与验收规则另放宿主文档。通用规则从包内
    `templates/任务协作规则.md` 拷贝后由宿主维护，kit 不反向覆盖。
35. 协调者必须独立复跑，并提供绑定交付 SHA 的独立代码审查；改变产品行为时必须要求独立产品评审。
    验证命令须接受工具提供的新空目录，**不得**覆盖原始证据或修改交付代码、HEAD 与输入。
    代码和材料变化后必须重验；进程成功、最近复跑与正式验收分别读取，历史已集成不得宣称当前版本重验通过。
36. 范围或验证方法变化须先经项目审批，再提交并重新确认定义。待验收任务需要续跑时，先正式登记返工说明，
    再恢复原会话；**不得**跳过返工登记直接续跑。
37. 已派发的固定起点**不得**改写历史。起点脱离主仓历史时，保留原树和材料；待验收任务先登记基准改写的
    返工原因，再在原树核对两边内容并变基或重放。重新确认基准不能代替冲突处理，交付变化后必须重新复跑和审查。
38. 独立复跑期间，主仓受跟踪文件、暂存区、分支与 HEAD 必须保持静止。任务执行期间允许协调者快进合入
    其他任务，但不得留下未提交改动；收尾提醒中的新增提交必须逐条核对内容，确认来自协调者的合入。
    **不得**用隐藏索引标记掩盖工作副本变化。
39. 主仓出现异常审计时，协调者必须核对现场和异常记录；确认保留内容也要登记依据，再用
    `verify --main-review` 完整复跑。**不得**删除异常记录或把恢复干净当作异常已经通过；工具不自动回滚现场。
40. 并发派发使用独立等待进程与独立输出文件，或显式 `--detach` 后观察。协调者必须持续读取前台 `task watch`
    的结果，超时后继续观察，不能把进程会话编号当成完成通知或依赖跨会话唤醒。并发按共享账号额度安排；
    长流程保留阶段结果、检查点与下一步，单条命令和观察期限须适配宿主等待上限。
41. 升级前保留旧入口和原始控制记录，活动任务使用固定版本直到结束。version 2 以外的快照由对应旧版本读取，
    **不得**直接改版本号或用 `--refresh-definition` 绕过格式兼容。
42. 回收前必须归档原始运行、验证和审查材料，包括 `main-audit`、`main-audit-refs` 及核对记录；
    **不得**把不可再生证据目录列入 `disposable`。任务验收后，集成与发布继续遵守宿主规则。
