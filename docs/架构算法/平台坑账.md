# 平台坑账（登记册）

> 基准：0.8.0 / 2026-10-19

每一条都有真机、线上或真实进程复现证据。登记格式：现象 → 根因 → kit 里的防线（测试/断言/写死的配置）。
**新坑先在这里登记、补能复现的失败测试，再修实现**；没有防线的条目不许入账。机制原理见
[离线与升级](离线与升级.md)与[部署与回滚](部署与回滚.md)。

## PWA 与升级

| 现象 | 根因 | 防线 |
|---|---|---|
| 发布后用户死活停在旧版 | sw.js / version.json 被 HTTP 或 CDN 缓存 | nginx 样板 `private, no-cache`；deploy 上传前预检 |
| 升级探测永远「已是最新」 | version.json 进了预缓存，被钉在安装时的内容 | `nexusPwa` 写死 globIgnores；`verifyPwaBuild` 断言不在预缓存；请求 `?t=` + `no-store` |
| 点「立即更新」后永远停在「正在更新」 | prompt 制下 controllerchange 未必触发；嗅探先于 SW 安装完成 | 激活信号三线订阅（`subscribeNewSwActivated` 测试）；switching 兜底 |
| 确认升级后刷新又回到旧版并再弹窗 | 新 SW 还没下来就刷新，入口页仍由旧预缓存供给 | 只在新 worker 激活后刷新；「active 就是本页控制者」不算激活（测试钉住） |
| 服务器没有新 SW 时升级幕布干等一分钟 | 嗅探与 SW 不同步时只靠绝对兜底 | no-install 提前收口（`upgrade-flow` 测试） |
| 慢网升级在下载途中被中断 | 固定短超时打断真实安装 | installing 在跑只受绝对兜底约束（测试钉住） |
| 并发探测重复下载 | 心跳、切前台、手动检查同时触发 update() | 在途探测去重（控制器单通道） |
| 回头客点强制更新原地打转 | 本会话还没接线 SW，被误判为无 SW 直接刷新，旧壳又把旧版端回来 | `ensureRegistration` 先接管浏览器真实注册再判定（测试） |
| 升级前保存卡住，用户被锁在弹窗里 | 保存钩子无超时、按钮全禁用 | `usePwaUpdate` 保存超时按失败处理、保存期间「稍后」可取消（测试） |
| 点「立即更新」没反应 | 保存失败没有提示 | `save-failed` 原因与模板文案（测试） |
| 「稍后」之后想更新找不到入口 | 只能等下一个构建或去找手动检查 | 快照 `needRefresh` + `reopenPrompt`，模板「有新版本」入口（测试） |
| 更新完不知道更新上了没有 | 刷新前后页面一样 | 升级前记旧版本，新版启动 `consumeUpdatedNotice` 提示一次（测试 + e2e） |
| 双击确认叠出两层幕布 | 保存期间弹窗仍可点 | `createUpgradeGate` 重入闸（测试） |
| 「稍后」之后每 15 分钟又弹 / 长会话永不再提醒 | 同一构建重复通知；稍后记忆不过期 | 稍后按构建号记忆、24 小时过期（控制器测试） |
| 同版本热修弹窗重列旧条目 / 内容改了却只说「修复」 | 同版本重发未区分 | 条目指纹比对 hotfix/revised（`version-check` 测试）；`verifyPwaBuild` 断言 bundle 带指纹 |
| 实机验收看到的还是旧代码 | 旧 SW 壳用缓存顶替新构建 | `?nosw=1` 验证开关 |
| 运行时资源发新版后仍是旧的 | 不带哈希的文件名 + 手动版本号漏 bump | 分区内容指纹仓名；`verifyPwaBuild` 按 public 实测对账 |
| 旧运行时仓一直占配额 | workbox 只清预缓存仓 | 生成式清理脚本（`runtime-cache` 测试在 vm 里跑真脚本） |
| 预载图离线时空一块 | 换了后缀忘改 globPatterns，glob 不匹配只报 warning | `verifyPwaBuild` 断言 preload 图在预缓存；默认 glob 不放可能不存在的目录，免得警告成噪音 |
| 首访首屏被拖慢、SW 越装越装不上 | SW 预缓存与首屏抢带宽 | `startWhenIdle()` |
| 构建号回退后老用户升级弹窗失明 | 计数器不入 git，丢失后从 0 重建 | 计数器缺失时警告指向真实号来源；deploy 硬校验新号大于现役 |
| dist 半新半旧被部署 | 构建中断或改完没重建 | bundle 构建号字面量与 version.json 互证（verify-build 与 deploy 共用断言） |

## iOS 与全屏

| 现象 | 根因 | 防线 |
|---|---|---|
| standalone 底部空一条 | black-translucent 下 viewport 少算状态栏高度 | 模板 `100lvh` + display-mode 限定 |
| 用 fixed 撑满仍缺一截 | iOS 把 fixed 裁在 layout viewport 内 | 模板根容器 absolute 铺满 body |
| 改了 apple meta 不生效 | 添加到主屏幕时固化 | 接入规范写明：改后删图标重装 |
| 点按出现半透明黑块 | 移动浏览器点按高亮 | 模板 `-webkit-tap-highlight-color: transparent` |
| Android 取消过一次安装后按钮点不动 | `beforeinstallprompt` 事件只能 prompt 一次 | 用过即作废、入口隐藏（测试） |
| 微信里照引导找不到「添加到主屏幕」 | 内置浏览器没有该功能；Safari 分享按钮位置随版本变化 | `iosBrowser` 分支引导文案（测试） |
| 装到主屏后进度全没了 | iOS 上 Safari 与主屏应用存储隔离 | 模板引导写明「记录不会带过去」；接入规范要求有数据的应用提供导出（待真机复核） |
| iPad 被当成桌面不出安装引导 | iPadOS 13+ UA 伪装 Macintosh | `isIOS` 以多点触控辅助识别（测试） |

## 日志与诊断

| 现象 | 根因 | 防线 |
|---|---|---|
| 导出的日志里启动、存档、升级那几条全没了（旧项目A 跑图十几分钟后） | 单一环形缓冲被高频事件冲满，低频事件被挤掉 | 按模块分区、各区独立淘汰（`ring` 测试）；接入规范第 25 条 |
| 刷新、升级、崩溃后上一局的日志没了 | 日志只在内存里 | 防抖落盘、页面隐藏与 pagehide 立即写、启动读回且不进本次缓冲（`store` 测试 + e2e） |
| 调试时开了详细日志，之后一直刷屏、挤掉关键记录 | 详细日志开关记在持久存储里 | `?log=debug` 只记 sessionStorage（`store` 测试） |
| 日志看着完整，其实写盘一直失败 | 配额满或隐私模式下 setItem 抛错被吞 | 失败计数与原因写进导出头部（`store` 测试） |
| 一条带循环引用的日志让整份持久化失败 | 落盘时整段 JSON.stringify 抛错 | 写入时逐条规整，不可序列化与过长载荷就地降级（`store` 测试） |
| 页面从往返缓存恢复后，下次启动误判「上一局正常关闭」 | pagehide 写了告别，页面却复活继续运行 | `pageshow` persisted 时撤销告别、重写开启（`forensics` 测试） |
| 「疑似异常退出」被当成崩溃结论 | 系统杀进程、用户划掉都表现为没有告别 | 判词文案写明不能证明死因；导出写「最后有动静」而非死亡时刻（`forensics` 测试） |
| 同一应用开在两个窗口，下次启动误判上一局异常或正常；一个窗口的日志把另一个冲掉 | 取证标记全应用共用一份；落盘时用启动时读到的旧历史整体覆盖 | 会话表每会话一行、读改写只动本行；落盘与导出现读其他会话（`forensics`、`store` 测试） |
| 闪退后马上重开，判词却是「无法判定」 | 只看心跳分不清「还开在别的窗口」和「刚死掉」 | Web Locks 存活锁：锁不在即已结束（`forensics` 测试 + e2e） |
| 存储被禁用的环境里整页白屏 | 访问 `localStorage` 属性本身就抛 SecurityError，取证在模块顶层执行 | `safeGlobalStorage` 兜底（`util`、`forensics` 测试） |
| `log.error("失败", err)` 导出里只剩 `{}` | `JSON.stringify(Error)` 不含 message 与 stack | 规整时展开 Error（`store` 测试） |
| 点了按钮报错卡死，诊断文件里却没有报错 | 未捕获异常与没人处理的 Promise 拒绝没进日志 | `captureGlobalErrors`，同条一分钟一次、每分钟有总数上限（`errors` 测试 + e2e） |
| 诊断文件里带出了 URL 里的令牌 | 日志消息与载荷是自由文本 | 导出时全文去 URL 查询串（`util`、`store` 测试 + e2e） |
| 微信里提示「已下载」却找不到文件 | 下载兜底拿不到成功信号，却按成功提示 | 结果语义为「已触发下载」，模板文案如实说「已开始下载」并给找不到时的办法 |
| 连点版本号到第 3 下出现「再点 2 次」，之后怎么点都导不出 | 提示是页脚里的一个居中元素，一出现就挤动版本号，手指按原坐标点空 | 提示浮层不参与排版；e2e 按固定坐标连点并断言版本号不动（换回旧排版实测会失败） |
| 一打开就白屏的用户导不出诊断文件 | 入口在页面上，页面没起来入口就没有 | 白屏兜底整页面板：挂载前异常经宽限期、渲染崩溃经错误边界（`fallback` 测试 + e2e） |
| 开着诊断弹层时界面崩溃，关掉弹层后一片白、兜底不再出现 | 面板单例直接返回已开的弹层，兜底已标记显示过 | 要整页时顶替弹层（`panel` 测试） |
| 慢机上（或先读存档再挂载）一个无关报错让整页兜底盖住正常起来的应用 | 宽限期满就显示，不看页面是不是真白、之后挂载成功也不撤 | 宽限期到时先看 `isBlank`；宽限期触发的兜底在 `markMounted` 时撤下（`fallback` 测试） |
| 兜底撤下后紧接着渲染崩溃，最后一片白、没有任何出口 | 撤下时没清「已显示」标记，之后的 report 被挡住 | 撤下时清标记（`fallback` 测试） |
| 慢启动的宿主每次进来都闪一下「应用出错了」 | 挂载前有无关报错（如注入脚本）、页面还是白的，宽限期一到就显示，挂载后才撤 | 接入规范要求慢启动宿主挂载前往 `#root` 画加载态 |
| 兜底页点「重新加载」还是坏的旧版 | SW 提示升级制：修复版要用户在升级弹窗里确认才接管，兜底时弹窗已不在 | 兜底的重新加载先激活已下载的新版本（`guard` 测试 + 升级链 e2e，含反向验证；需求裁决的唯一例外） |
| 兜底页点「重新加载」后按钮变灰、什么都不发生 | 取 SW 注册信息在 iOS 上偶尔一直不返回，而时限只管后半段 | 绝对时限兜住每一步（`guard` 测试） |
| 没有修复版时点「重新加载」白等 4 秒，像是点了没反应 | 检查完更新没有新版本仍等满时限，按钮外观不变 | 检查结束无新版本立即刷新；按钮变暗并显示「正在检查 / 正在下载新版本」（`guard`、`panel` 测试） |
| 主包没加载上，一片白、什么都没有 | 主包失败时整个模块图不执行，runtime 兜底没装上 | 注入 `<head>` 的内联兜底，以 `markBooted` 交接（e2e 拦主包请求） |
| 弱网下「加载失败」页误报后一直盖着已经跑起来的应用 | 内联兜底显示后没有撤下路径；图片、样式表失败也算 | `markBooted` 撤下已显示的页；只认模块脚本加载失败（e2e 两个误报场景） |
| 内联兜底在旧浏览器上整段解析失败 | 手写在 index.html、被格式化工具加上了 ES2017 尾逗号；与 runtime 逻辑各写一份 | 单一源码只用 ES5、构建时生成，单测用 ES5 解析器校验 |
| 截短提示指向「发送诊断文件」，桌面上却叫「下载诊断文件」 | kit 里写死了按钮名 | 省略说明由宿主传入；按钮改名「复制诊断内容」 |
| 复制的诊断贴不进微信 | 日志多时全文几十 KB | 复制截短：头部完整、日志取最近的行并注明省略数（`truncate` 测试；上限未实测） |
| 微信里下载失败提示去复制、复制失败又提示去下载，绕不出来 | 两条退路互相指向 | 失败提示统一给「在浏览器打开」这条出路（模板文案） |
| 双击「发送诊断文件」多下载一个文件 | 第二次分享因上一次未结束抛 InvalidStateError，落到下载兜底 | 处理中按钮禁用（`panel` 测试） |
| 微信里分享和下载都没反应，诊断发不出来 | 应用内浏览器限制系统分享与 blob 下载 | 面板加「复制诊断内容」，剪贴板 API 不行时退回复制命令（`deliver` 测试 + e2e） |
| 桌面上连点版本号弹出系统分享面板 | Chrome、Safari 桌面版也支持带文件的分享 | 只在粗指针（触屏）设备优先分享，桌面直接下载（`deliver` 测试） |
| 系统分享面板里点了取消，又弹出下载 | 把 AbortError 当成分享失败走了兜底 | AbortError 返回取消，只有其他错误才下载（`deliver` 测试） |

## 性能采集

取材 旧项目A 的 `observe/` 与 `docs/架构算法/性能与显存.md`。

| 现象 | 根因 | 防线 |
|---|---|---|
| 切一次后台，帧统计多出一个几十秒的「卡顿」 | 后台时 rAF 停摆、宿主循环被冻结，回来的第一帧间隔是整段后台时长 | 超过 1 秒的间隔算暂停，不算卡顿、不进帧率（`frames` 测试） |
| Safari 上 JS 堆走势是一条 0 线，看着像没用内存 | Safari 不提供 `performance.memory`，读不到被记成 0 | 读不到、抛错、非有限数一律记 null，走势跳过 null（`index`、`vitals` 测试）；接入规范要求宿主指标同样返回 null |
| 泄漏看不出来：截面数字正常，十几分钟后才发作 | 帧环只留 60 秒，只能看截面 | 5 秒一点、约 2.8 小时的水位长线，导出给首尾、净增与峰值（`vitals` 测试） |
| 闪退后重开，上一局最后的状态全没了 | 水位只在内存里，刷新即失 | 每次采样把本局最后 120 个点写盘，下一局导出（`persist`、`index` 测试；e2e 杀进程后读回被杀那一局） |
| 同一应用开两个窗口，只剩一个窗口的水位 | 整键覆盖写，后写的窗口盖掉先写的 | 会话表每会话一行，读整表只改本行（`persist` 测试） |
| 二次启动的网络账看着是 0KB、像没加载资源 | 缓存命中的 `transferSize` 为 0 | 走网络的字节与缓存命中数分开记（`boot` 测试） |
| 一次启动在画像里占两条，挤掉更早的启动 | 挂载时与 load 后各采一次 | 同一会话号再采覆盖前一条（`boot` 测试） |
| 纹理字节记到了别的纹理上（代码评审发现） | 绑定只按目标记，切纹理单元后上传的是另一个单元的纹理 | 绑定按「纹理单元 × 目标」记（`gl` 测试） |
| 页面上缩放显示的图片按显示尺寸估了显存（代码评审发现） | `<img>` 的 `width` 是 CSS 渲染宽度 | 取 `naturalWidth`，`VideoFrame` 取 `displayWidth`（`gl` 测试） |
| 宿主登记了叫 `fps` 或 `t` 的指标，内置帧率被覆盖、JSONL 行结构坏掉（代码评审发现） | 指标与内置读数、行字段共用一层命名 | `registerGauge` 拒绝保留名（`index` 测试） |
| 宿主指标每次都抛错，导出里一直是 null 却看不出原因（代码评审发现） | 读数异常被吞掉 | 按指标与原因记一条 warn（`index` 测试）；存储用量、长任务、性能条目、画像与水位读写同样处理 |
| GL 计数出现负数 | 装计数器之前创建的对象被删除时也被扣减 | 只扣经计数器创建的对象（WeakSet，`gl` 测试） |

## 图像资源

取材 旧项目A 的 `load/` 与 `docs/架构算法/性能与显存.md`。

| 现象 | 根因 | 防线 |
|---|---|---|
| 高延迟链路上进图要几十秒 | 图集页逐张 `await` 串行，耗时 = 请求数 × 单次延迟（真机 34 页 34.7 秒） | `mapLimit` 限并发批量；调度器并发上限默认 6（`tasks`、`loader` 测试；e2e 断言峰值不超上限） |
| 慢网下第一眼要看的图迟迟不出来 | 几十个不急的请求同时抢带宽；fetch priority 在 Safari 上无效 | 关键闸门：关键图有结论前档位 2、3 不发，封顶时限防饿死（`loader` 测试；e2e 用请求时间戳断言，去掉闸门即变红） |
| 同一张图下了两次 | 预热与正式取用用了不同的调度键，两边同时在飞 | 调度器按 URL 去重，在飞或排队时共用结果（`loader` 测试；e2e 断言只请求一次） |
| 换页后内存峰值远高于实际需要 | 解码位图只置空引用要等 GC，新旧两份同时活着 | 引用计数 + LRU 预算，淘汰即 `close()`（`image-cache` 测试；e2e 断言被淘汰位图宽高为 0） |
| 图片取消后仍常驻内存、预算失效（代码评审发现） | 解码刚完成、调用方在拿到结果前取消，引用归零却没进 LRU | 引用归零的图统一经一个出口进 LRU 并按预算淘汰（`image-cache` 测试复现这个时序） |
| 批量加载一项失败后还在继续发请求（代码评审发现） | 并发 worker 互不知道别的 worker 已失败 | 失败后不再取新项；并发数非法直接抛错，不再静默一项不跑（`tasks` 测试） |
| 首屏期间的空闲任务在 iOS 老版本上报错 | iOS 16.4 以前没有 `requestIdleCallback` | `whenIdle` 退到定时器（`tasks` 测试） |

## 音频

取材 旧项目A `load/audio.ts` 与旧项目B `lib/audio/`。Chromium 模拟不了的几条，防线只到单测接线，真机清单见[音频](音频.md) §6。

| 现象 | 根因 | 防线 |
|---|---|---|
| iOS 锁屏或切后台回来永远没声 | AudioContext 进了 `interrupted`（标准外的第四态），只判 `suspended` 不会 resume | 不在 running 一律 resume（`host` 测试） |
| iOS 回前台偶尔不恢复 | `visibilitychange` 在 iOS 上会漏触发 | 同时听 `statechange`（`host` 测试） |
| 第二次退后台回来背景音乐永久没声 | 系统掐死循环声源，播放指令只在进场景时发一次 | 记「应当在响的曲子」，回到 running 时校对重播（`samples` 测试；e2e 断言重建后续播） |
| 点屏幕也救不活的全哑 | 引擎卡进 resume 无效的死态 | resume 落地仍不 running 或被拒就换新 context，上限 3 次（`host` 测试；e2e 用 `close()` 模拟） |
| 引擎挂起时的音效是哑的 | 音符排在冻结的时间轴上 | `whenRunning` 先 resume 再发声（`host` 测试；e2e 断言） |
| 切曲后旧曲又冒出来 | 旧曲解码晚到，顶掉新意图 | 切曲取号，结果落地前验号（`samples` 测试） |
| 升级音晚 8 秒才响 | 慢网懒解码，晚到也照播 | 补播时限 300ms，过时即丢（`samples` 测试；e2e 断言） |
| 重建后所有音效都不响 | 限频按 `ctx.currentTime` 记账，新引擎时钟从零起步 | 限频按墙钟，重建时清账（`samples` 测试） |
| 缺失的音效每次触发都发一个 404 | 失败不分级，一律重试 | HTTP 错误码与解码失败永不重试，已知缺失直接静默（`samples` 测试；e2e 断言只请求一次） |
| 音效排在地图页后面，过了补播时限被丢 | 真触发和预热走同一条排队 | 真触发直接下载，同 key 排队中的预热先撤回（`samples` 测试） |
| 一个下潜来源撤销，把另一个来源的下潜也撤了 | 下潜只有一个开关 | 按来源登记，取最深一档（`host` 测试） |
| 重建后解码字节水位虚高、永不回落（代码评审发现） | 重建前发起的下载落地后在新引擎上解码，同 key 再入缓存时没扣旧字节 | 解码在等字节前记下引擎、换了就作废；入缓存先扣旧条目（`samples` 测试复现） |
| 快速切后台再回来，主音量停在静音（代码评审发现） | 淡出渐变还在时间线上，直接赋值挡不住 | 设主音量前先撤掉未执行的渐变（`host` 测试） |
| iOS 停麦后声音变得极轻 | 系统把输出路由劣化，引擎状态仍是 running | `resetSession` 挂起 120ms 再恢复（`host` 测试；真机清单） |

## 任务协作

| 现象 | 根因 | 防线 |
| --- | --- | --- |
| 任务收尾后主仓 amend，verify 通过但集成可能发生 add/add 冲突 | 固定起点只与任务分支对账，没有与当前主仓历史对账 | dispatch、resume、verify、accept 检查主仓祖先关系并告警；公开 CLI 核对 SHA、处理步骤及不改固定起点 |
| 待验收交付在主仓历史改写后按告警变基，刷新定义被拒，再 verify 仍失败（独立产品评审复现） | 恢复指引没有说明基准调整也需要先登记返工 | 起点告警与交付基准错误共用恢复步骤，待验收先登记返工原因，再变基、续跑重新确认和验收；公开 CLI 覆盖恢复全过程 |
| 任务定义返工并重新确认后，accept 拒绝旧验证材料却不给新旧指纹（独立代码审查复现） | 验证材料定义比较混在通过状态与任务标识检查里 | 定义 SHA-256 独立使用指纹诊断；公开 CLI 覆盖定义返工、重新确认、忘记重验的工作流 |
| 待验收任务续跑被拒绝，报错没有下一步 | 启动状态校验只输出状态；会话缺失还可能抢先报错 | 派发、续跑先说明返工登记、JSON 必填项和后续命令；公开 CLI 核对拒绝时 HEAD 不变 |
| 输入指纹报错只有路径，协调者需要手算才能对账 | 指纹比较没有输出登记值与当前值 | SHA-256 比较共用期望值、实际值诊断；公开 CLI 用错误输入指纹复现 |
| 进度采样异常后 run.json 停在 running，执行器还在运行 | 异步定时器抛错绕过外层 try/finally | 预算、进度、会话采样和硬期限共用 guarded，失败终止进程并保存可保存的收尾；公开 CLI 失败测试损坏临时任务树 Git 现场 |
| dispatch 已成功返回，后代仍可改任务树，verify 因活动进程被拒绝 | 成功退出只等待先前触发的终止，不检查残留进程组 | 每次监督收尾都检查并清理进程组；成功交付且后代忽略 TERM 的公开 CLI 测试 |
| 前置 receipt 被改坏，status 显示材料错误，下游仍能派发 | 前置只对账 HEAD，不校验正式验收材料 | status、前置与 accept 共用正式 receipt、日志、产物指纹核对；覆盖原树存在及已集成回收、日志和产物变化 |
| 硬期限中断后，任务树最后一个提交是执行器后代写的，中断记录夹在中间或因 index.lock 丢失（代码评审发现） | 中断记录在 catch 里提交，进程组收尾在 finally 里，后代仍在 TERM 宽限期内写树 | 中断记录挪到进程组确认退出之后；后代收到 TERM 后延迟提交的公开 CLI 测试 |
| 宿主照规范接入，带外部输入的任务 verify 永远报任务树有未提交内容（代码评审发现） | start 把未提交的输入复制进任务树，成为未跟踪文件 | dispatch 与 start 拒绝既未提交也未被 Git 忽略的输入；加入忽略后复制、复跑通过的公开 CLI 测试 |
| git 默认配置下，中文规则文件或中文输入被报“未提交”，派发被拒（代码评审发现） | `ls-files` 输出受 core.quotepath 转义，与原路径逐字比较不相等；带 `*`、`[` 的路径还会被当成通配 | 已提交判断改用 `ls-files -z` 加 literal pathspec，输入以 HEAD 中是否存在为准；强制 quotepath=true 的公开 CLI 测试 |
| 一个任务的树切错分支或定义写坏，status 与 status --short 整体报错（代码评审发现） | 逐任务读取在同一个 map 里直接抛错 | 按任务捕获，只在该行给 error；规则文件按 task.rules 排除，不写死文件名 |
| hardTimeoutMinutes 配成 40000，执行器刚启动就被终止（代码评审发现，Node 实测 2 毫秒触发） | Node 定时器超过 2³¹−1 毫秒时改为 1 毫秒 | 分钟类配置上限 35791、验证期限上限 2147483 秒，配置与任务定义超限拒绝 |
| 源码已修改，单独跑覆盖率却测到旧 dist | 子进程测试读构建产物，覆盖率入口没有先构建 | test:task 自行构建 devflow，再采集 task 四项覆盖率；test:coverage 与 check 都调用同一入口 |
| 执行器停在“请确认计划”，退出码 0 但没交付也没标受阻，运行被记成 failed，协调者误判执行器损坏（旧项目C 真实任务复现） | 派发提示词没有说明派发即批准任务范围内计划，执行者按自身确认习惯停下等待，退出成功却被记为失败 | 结束分类识别计划停等记为 needs_approval 并追加结束流水，status 显示分类且不改写真实退出码；派发与续跑提示词写明派发即批准、不结束回合等重复批准；公开 CLI 覆盖英文停等回复、真失败、受阻与成功回复含计划字样的区分，以及流水不可写时保留诊断 |
| opencode 免费模型限流，执行器在 task start 建树前退出；之后 `dispatch --refresh-definition --model` 换模型报裸 ENOENT，任务卡在不能换模型（kit 临时仓库实跑 opencode 复现） | 重新确认无条件对原工作树取 realpath，没有区分“从未建树”和“树丢失” | 任务分支不存在且主仓状态为待认领时允许在主仓重新确认并归档旧快照；分支已存在而树缺失时报“原任务工作树不存在”；公开 CLI 覆盖两种情形 |
| 0.7.0 冻结的快照在新版本 resume 带 `--model` 抛 TypeError，不带也报“项目配置已变化”（代码评审发现） | 快照按原始 JSON 返回，旧 config 没有 executors；配置指纹按新形状重算，与旧形状哈希必然不同 | 读取快照时把 config 规范成执行器形状；配置检查另按 0.7.0 形状算一份指纹比对；公开 CLI 用 0.7.0 形状快照覆盖直接续跑与 `--model` 提示 |
| 监督进程被 SIGKILL 后，`task watch` 一直等到 45 分钟超时才退出（代码评审发现） | 观察器只看 endedAt，不检查监督进程存活 | 观察器与 status 共用 settleRun 判定孤儿记录为中断；观察器测试用已退出的进程号覆盖 |

前置任务树也可能用 assume-unchanged 或 skip-worktree 隐藏未提交内容。派发前置与独立验证共用 assertClean，公开 CLI 负例分别核对两种索引标记；前置 HEAD 等于验收登记提交不能替代工作副本检查。

任务执行者直接修改主仓共享文档，协调者的登记提交可把改动带入历史。任务树提交 diff 的白名单检查无法覆盖主仓绝对路径写入，事后主仓干净也不代表没有越权。main-audit 在 dispatch/resume 和每条复跑命令前后核对主仓 HEAD、索引与受跟踪内容；异常审计在后续提交后仍阻止验证与验收，协调者核对记录与审计一起绑定验证材料。执行窗口内主仓快进出的新提交只提醒不判失败，否则协调者每次在任务运行时合入其他任务，都会让运行中的任务被判 failed，核对记录沦为例行签字。公开 CLI 测试覆盖主仓未提交、暂存、隐藏索引、执行中改写历史、执行中快进只提醒、协调者后续提交、resume 越权、复跑命令越权及验收材料删除。
